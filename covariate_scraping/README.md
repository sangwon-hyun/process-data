# Running `covariate-scrape-process.R`
 
Colocalizes Simons CMAP environmental variables with one or more cruise tracks, assembles the results into analysis-ready matrices, and generates (and saves) diagnostic plots.

## Requirements
 
- R packages: `tidyverse`, `cmap4r`
- A Simons CMAP API key, exported as the `CMAP_APIKEY` environment variable
- `catalog.csv` in the same directory as the script (can be generated by `catalog-scrape.R`, but check that table format matches)
- Access to the UCSC Hummingbird HPC cluster (Slurm)

## Setup
 
1. Replace `YOUR_CMAP_API_KEY` in `covariate-scrape-process.R` with your actual CMAP API key
2. Set `COVERAGE_THRESHOLD` at the top of the script (e.g. 0.5 = 50%)
3. Ensure `catalog.csv` is in the same directory as the script

### Hummingbird setup:bgxs4
* Connect to `vpn.ucsc.edu` through Cisco Secure Client
* Activate hummingbird: `ssh <YOUR_CRUZ_ID>@hb.ucsc.edu`
* Load miniconda: `module load miniconda3/3.13`
* Create a virtual environment and then activate it: `conda activate <ENV_NAME>`

### Script configuration

1. Set `R_BIN` in `covariate-scrape-process.slurm` to your `whereis Rscript` output
2. Set `--mail-user` in `covariate-scrape-process.slurm` to your email
3. Set `COVERAGE_THRESHOLD` at the top of `covariate-scrape-process.R`
4. Copy .Renviron.example to .Renviron and fill in your CMAP API key 

## Running
 
```bash
sbatch --export=ALL,cruise_ids="KOK1606,MGL1704,KM1906" covariate-scrape-process.slurm
```

Use no spaces in the cruise list. One submission handles any number of cruises and runs the full pipeline. 

### How to test it with fewer variables:

`n_vars` overrides the array size, running only the first N rows of the catalog:

```bash
sbatch --export=ALL,cruise_ids="KOK1606",n_vars=1 covariate-scrape-process.slurm
```

The heatmap produced by a test is not meaningful, since the test cruise
will have near-zero coverage on every variable it did not scrape. It only
confirms the script works.


## What it does

1. **Catalog refresh** (once per submission): `catalog-scrape.R` downloads the
   current CMAP catalog to `catalog.csv`. Every array task reads this same static csv
   file, so the array index to variable mapping stays fixed for the whole run.

2. **Colocalization** (one Slurm array per cruise, one task per variable):
   queries CMAP via `along_track()` using adaptive space-time tolerance boxes.
   For each variable, the tightest tolerance achieving full coverage is used.
   Results are saved as `data/<CRUISE_ID>/<variable>.csv`. Variables already
   present on disk are skipped, so reruns resume rather than restart.

3. **Finalize** (one job, after all arrays finish): assembles every cruise, then
   generates line plots for every cruise, then one heatmap. The two passes matter:
   plot filtering depends on coverage across all cruises, so every cruise must be
   assembled before any plotting happens.

   Assembly produces the following (for each cruise):
   - `X.csv`: mean colocalized values (T x p)
   - `X_std.csv`: within-window standard deviations (T x p)
   - `X_box_space.csv`: lat/lon tolerance used per variable, in degrees
   - `X_box_time.csv`: temporal tolerance used per variable, in hours

## Modes (run these to debug)

The launcher handles these automatically, but you can run these directly for debugging:

```
Rscript --no-save covariate-scrape-process.R <CRUISE_ID> colocalize <ROW_INDEX>
Rscript --no-save covariate-scrape-process.R <CRUISE_ID> assemble
Rscript --no-save covariate-scrape-process.R <CRUISE_ID> lineplots
Rscript --no-save covariate-scrape-process.R ALL heatmap
Rscript --no-save covariate-scrape-process.R "<ID1>,<ID2>" finalize
```
